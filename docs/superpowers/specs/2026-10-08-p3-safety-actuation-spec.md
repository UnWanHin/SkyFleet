# P3 规格：本地安全动作闭环（致动）

对标：设计文档 §7.4（本地安全动作的触发与动作）、§16.2 第 2 条
（已知缺口：「安全动作只写日志、从不执行」）。

## 1. 现状与缺口

`_check_safety`（`skyfleet/sim/engine.py`）每周期计算一次
`safety_decision(...)`，把结果写进 `SAFETY_ACTION` 事件，**然后就没有下文**。
`RETURN` 不返航、`HOVER` 不悬停、`HOLD` 不停住——这直接回答了设计文档
里「会不会掉机」的问题：**不会，因为没有任何机制把安全决策接到飞行上**。

另有两处与文档不符：

| # | 问题 | 证据 |
|---|---|---|
| 1 | 动作从不致动 | §16.2 已记录，本轮修复 |
| 2 | **触发条件与 §7.4 不符** | §7.4 要求「与主节点**及所有中继**失联」，实现只检查主节点 |
| 3 | `SafetyAction.DESCEND` 不可达 | `safety_decision` 的四个分支只返回 HOLD/RETURN/HOVER/NONE |

缺口 2 有实测证据：基线场景 t=332.0 **全部 10 个节点同时**报 `LINK_LOST`。
主节点心跳一直规律（600 次、无 >1.5s 间隔），只是 t=329.47→332.45 之间
有 3 秒接收空窗（普通丢包）。此时中继完全可达，按 §7.4 **不应**触发。

## 2. 关键设计决策：致动阈值必须比记录阈值保守

基线里 **22 次 `LINK_LOST` 全部是暂态**，持续 **1~5 秒**即恢复（实测）。

因此**不能**用记录用的 2 个心跳周期去致动：那会让节点在普通丢包时
反复停飞 1~5 秒。对配送无人机而言，短暂失去上行链路就停在半路，
比继续飞更糟。

| 用途 | 阈值 | 理由 |
|---|---|---|
| **记录** `SAFETY_ACTION` | 2 个心跳周期 | 可观测性：任何降级都要留痕，便于复盘 |
| **致动** | **10 个心跳周期**（`SAFETY_ACT_TIMEOUT_FACTOR`）| 只在**持续**失联时才改变飞行 |

两者分开是刻意的：**「值得记录」与「值得据此改变飞行」不是同一件事**。
把两者绑成一个阈值，就会被迫在「漏记降级」和「过度反应」之间二选一。

## 3. 动作语义

| 动作 | 致动 | 恢复 |
|---|---|---|
| `NONE` | — | 恢复进入安全状态前保存的航线 |
| `HOVER` | 清空航线（原地悬停）| 条件消失时恢复原航线 |
| `HOLD` | 清空航线（不再外飞）| 同上 |
| `RETURN` | 改飞**本机起飞点** | 同上 |
| `DESCEND` | **不可达，刻意保留** | 见 §4 |

**必须显式保存/恢复航线**：`_advance_mission` 只在**到达航点**时被推进，
航线一清空就再也不会被调用——不恢复的话，节点会永久悬停、任务卡死。
这是本切片最容易写错的地方，已用测试固定。

## 4. `DESCEND` 的处理：如实保留为不可达

§7.4 写「低电量 → `RETURN` **或** `DESCEND`」——是**或**，选 `RETURN`
即满足要求。要有意义地使用 `DESCEND`，需要「能否返航」的续航判断
（剩余电量 vs 返航所需电量），那是新的物理建模，不应顺手发明。

因此 `DESCEND` **保留为不可达值**，并用测试把它钉住，让「不可达」是
一个**明确决定**而不是漏看。将来要接真实续航判断时，该测试会失败并
提示此处需要配套实现。

## 5. 对黄金摘要的影响

致动会改变飞行轨迹 → 改变日志 → **黄金摘要必须重订基准**。

按 `test_golden_digest.py` 的既定协定执行：先确认是有意为之 → 在设计
修正记录写明 → 更新 `GOLDEN`。顺序不得颠倒。

**实测结论：基线场景的行为未变，仅日志内容增加。**

逐事件对比 HEAD 与改动后的基线日志（56588 个事件）：

```
差异分类：
  kind=SAFETY_ACTION 新增字段=['actuated'] 移除=[] 值变=[] 共 54 笔
      actuated: None -> False
有差异的事件数: 54 / 56588
```

**56534 个事件逐字节相同，没有任何字段的值发生变化。** 所有指标
（完成率、丢弃率、时延分位数、路由切换、转发量、开销）逐项一致，
安全动作分布也相同（`NONE` 32 / `HOVER` 22）。

这**推翻了本节初稿的判断**（初稿写「本轮行为确实改变」）。原因是
设计使然：基线最长失联 5s < 致动阈值 10s，因此基线不触发任何致动。
行为改变只发生在**持续失联**的场景（见 §6 验收 5）。

因此：**报告中已写入的数字不需要复核**；`GOLDEN` 的更新属
「仅日志内容增加」这一类，是该文件已有先例的第 3 次。

## 6. 验收

1. 触发条件符合 §7.4（主节点**及所有中继**失联）。
2. `HOVER`/`HOLD` 清空航线且**条件消失后恢复**（不是永久悬停）。
3. `RETURN` 飞向起飞点。
4. 基线场景**不触发致动**（最长失联 5s < 10s 阈值）——保证 2 个心跳
   周期的记录语义不变。
5. 持续失联场景**必须**触发致动（否则功能是空转的）。
6. `DESCEND` 不可达这一事实被测试钉住。
7. 全套测试通过；黄金摘要按协定重订基准并记录原因。
